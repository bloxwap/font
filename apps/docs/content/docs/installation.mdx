## Install on your computer

Use the **OTF** files for desktop apps (design tools, word processors). The variable TTF also works in apps that support variable fonts and gives you every weight in one file. Install one or the other, not both, or your apps will list duplicate styles.

<Tabs items={['macOS', 'Windows', 'Linux']}>
  <Tab value="macOS">
    Unzip the download, open the `otf` folder, select all files and double-click them. Click **Install** in Font Book. To install for all users, drag them to `/Library/Fonts`.
  </Tab>
  <Tab value="Windows">
    Unzip the download, open the `otf` folder, select all files, right-click and choose **Install for all users** (or **Install**). Restart apps that were already open.
  </Tab>
  <Tab value="Linux">
    Copy the files to `~/.local/share/fonts` (or `/usr/local/share/fonts` for everyone) and refresh the cache:

    ```sh
    mkdir -p ~/.local/share/fonts/BloxwapSans
    cp BloxwapSans/otf/*.otf ~/.local/share/fonts/BloxwapSans/
    fc-cache -f
    ```
  </Tab>
</Tabs>

## Use on the web

### Install from npm

`@bloxwap/font` has every family's variable WOFF2, the stylesheet and `next/font` exports:

```sh
npm install @bloxwap/font
```

Import the stylesheet once (any bundler), then use the family names as with the hosted stylesheet below:

```js
import '@bloxwap/font/css';
```

### Link the hosted stylesheet

The quickest option. One stylesheet defines `Bloxwap Sans`, `Bloxwap Mono` and `Bloxwap Pixel` with variable fonts, and merges the [companion scripts](/docs/multi-script) into the same family names:

```html
<link rel="stylesheet" href="https://bloxwap.github.io/font/bloxwap-font.css">
```

```css
body { font-family: "Bloxwap Sans", system-ui, sans-serif; }
code, pre { font-family: "Bloxwap Mono", ui-monospace, monospace; }
```

Core CSS splits each style into `latin`, `greek`, `cyrillic` and `other`, covering the full font. Greek and Cyrillic also carry the [explicit shared set](https://github.com/bloxwap/font/blob/main/packages/font/README.md#web-subsets) of combining marks, common punctuation and digits. Overlaps are limited to that set, and Latin is declared last to prefer it for independently matched common characters. Latin includes every Latin-script character, including Latin Extended, IPA and Vietnamese, plus its combining marks, punctuation, digits and currency. A Latin-only page loads 184,980 bytes of Sans upright instead of 310,848 bytes. Fonts download only when text uses them. For production we recommend self-hosting, so your site does not depend on another origin.

Each file retains every applicable layout feature; Latin words and accents stay together in one shaping font.

Shaping across mixed-script boundaries, such as Latin next to Greek inside one word, is outside the subset guarantee.

The npm entries `@bloxwap/font/css/sans-full`, `/mono-full` and `/pixel-full` provide complete core faces; the declarations below also use complete files.

#### Static fallbacks

Every current browser supports variable fonts. If you must support one that does not, add static WOFF2 files (from the zip's `woff2/` folder) inside a feature query, so modern browsers never download them:

```css
@supports not (font-variation-settings: normal) {
  @font-face {
    font-family: "Bloxwap Sans";
    src: url("/fonts/BloxwapSans-Regular.woff2") format("woff2");
    font-weight: 400;
    font-style: normal;
    font-display: swap;
  }
  @font-face {
    font-family: "Bloxwap Sans";
    src: url("/fonts/BloxwapSans-Italic.woff2") format("woff2");
    font-weight: 400;
    font-style: italic;
    font-display: swap;
  }
  @font-face {
    font-family: "Bloxwap Sans";
    src: url("/fonts/BloxwapSans-SemiBold.woff2") format("woff2");
    font-weight: 600;
    font-style: normal;
    font-display: swap;
  }
  @font-face {
    font-family: "Bloxwap Sans";
    src: url("/fonts/BloxwapSans-Bold.woff2") format("woff2");
    font-weight: 700;
    font-style: normal;
    font-display: swap;
  }
}
```

Static files are named `<Family>-<Style>.woff2`: `Thin`, `ExtraLight`, `Light`, `Regular`, `Medium`, `SemiBold`, `Bold`, `ExtraBold`, `Black`, and the same with `Italic` appended (the regular italic is just `Italic`).

### Preload the main file

When using the generated subset stylesheet, preload its upright Sans Latin subset so text renders in Bloxwap Sans on first paint. The `crossorigin` attribute is required, even for same-origin fonts:

```html
<link rel="preload" href="/fonts/BloxwapSans/variable/subsets/BloxwapSans[wght].latin.woff2" as="font" type="font/woff2" crossorigin>
```

Keep the subset stylesheet and its `fonts/` directory together when self-hosting; its URLs are relative. The complete files in the desktop zips still work with the full-font declarations above. Preload the exact URL your stylesheet uses.

## Expo / React Native

The 0.1.3 candidate ships native TTFs in opt-in packages, separately from the web fonts:

```sh
npm install @bloxwap/font-native
# Add only the companion scripts your app needs, for example:
npm install @bloxwap/font-native-kr
```

Use `require('@bloxwap/font-native/assets/BloxwapSans/BloxwapSans-Regular.ttf')`
for one face, or `import faces from '@bloxwap/font-native/BloxwapSans'` for a complete
family map. Script packages use the same structure, such as
`@bloxwap/font-native-kr/BloxwapSansKR`. Other script suffixes are `-arabic`, `-hebrew`,
`-armenian`, `-georgian`, `-jp` and `-sc`. All packages include the OFL-1.1 LICENSE.
Register the selected TTFs before rendering; see [Cross-platform typography](/docs/cross-platform)
for exact registration names, accessibility guidance and source-checkout builds.


## Next.js

The `next/font/local` API has no `unicode-range` per source. These exports therefore keep the complete core files and preload the full normal face. For automatic core subsets in Next.js, import `@bloxwap/font/css/sans` (or `/mono`, `/pixel`) and use the CSS family names instead.

With the npm package (Next.js 15 or later), import a family and add its class names. Each export comes from `next/font/local`, so Next.js self-hosts it and preloads the normal face (the italic, in the same family, downloads only when a page renders italic text); Sans and Mono include the script companions, downloaded only for text in those scripts:

```tsx title="app/layout.tsx"
import { BloxwapSans } from '@bloxwap/font/sans';
import { BloxwapMono } from '@bloxwap/font/mono';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" className={`${BloxwapSans.variable} ${BloxwapMono.variable}`}>
      <body className={BloxwapSans.className}>{children}</body>
    </html>
  );
}
```

The `variable` class names define `--font-bloxwap-sans` and `--font-bloxwap-mono` (and `--font-bloxwap-pixel` from `@bloxwap/font/pixel`).

### Without the package

Put the variable WOFF2 files next to your layout (for example in `app/fonts/`) and load them with `next/font/local` (Next.js 15 or later). Next.js self-hosts them, adds preload tags and generates a size-adjusted fallback.

`preload` applies to every file in a `localFont` call, so load the italics in a second call with `preload: false`. Assign it to a `const` with the same name: Next.js names the family after the `const`, so the italic joins the normal face's family and the browser downloads it only when a page renders italic text:

```tsx title="app/fonts.ts"
import localFont from 'next/font/local';
// The italic faces: same families, not preloaded.
import './fonts-italic';

// No `style` on a single src: next/font would copy it onto className and cancel inherited italics.
export const sans = localFont({
  src: [{ path: './fonts/BloxwapSans[wght].woff2', weight: '100 900' }],
  variable: '--font-bloxwap-sans',
  display: 'swap',
});

export const mono = localFont({
  src: [{ path: './fonts/BloxwapMono[wght].woff2', weight: '100 900' }],
  variable: '--font-bloxwap-mono',
  display: 'swap',
});
```

```tsx title="app/fonts-italic.ts"
import localFont from 'next/font/local';

// Keep these names equal to the consts in fonts.ts so each italic joins that family.
const sans = localFont({
  src: [{ path: './fonts/BloxwapSans-Italic[wght].woff2', weight: '100 900', style: 'italic' }],
  display: 'swap',
  preload: false,
  adjustFontFallback: false,
});

const mono = localFont({
  src: [{ path: './fonts/BloxwapMono-Italic[wght].woff2', weight: '100 900', style: 'italic' }],
  display: 'swap',
  preload: false,
  adjustFontFallback: false,
});

export { sans, mono };
```

```tsx title="app/layout.tsx"
import { sans, mono } from './fonts';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" className={`${sans.variable} ${mono.variable}`}>
      <body>{children}</body>
    </html>
  );
}
```

```css title="app/globals.css"
body { font-family: var(--font-bloxwap-sans), system-ui, sans-serif; }
code, pre { font-family: var(--font-bloxwap-mono), ui-monospace, monospace; }
```

For Bloxwap Pixel, load `BloxwapPixel[ROND,wght].woff2` and its italic the same way and set `ROND` with `font-variation-settings`.

## Tailwind CSS v4

Declare the families with `@font-face` (or the hosted stylesheet), then map them to theme variables in your CSS entry file:

```css title="app.css"
@import "tailwindcss";

@theme {
  --font-sans: "Bloxwap Sans", ui-rounded, system-ui, sans-serif;
  --font-mono: "Bloxwap Mono", ui-monospace, "SF Mono", Menlo, monospace;
  --font-pixel: "Bloxwap Pixel", "Bloxwap Mono", ui-monospace, monospace;
}
```

`font-sans` and `font-mono` now use Bloxwap Font, and the new `font-pixel` utility is available. Weights are ordinary utilities, and arbitrary values reach any point on the axis:

```html
<h1 class="font-sans font-semibold tracking-tight">Portfolio</h1>
<span class="font-sans font-[450] tabular-nums">$67,421.08</span>
<code class="font-mono">a !== b</code>
<div class="font-pixel text-6xl font-bold [font-variation-settings:'ROND'_60]">SCORE 9001</div>
```

With `next/font/local`, use `--font-sans: var(--font-bloxwap-sans), …` instead.

## CSS custom properties

Without a framework, keep the stacks in custom properties so every component uses the same fallbacks:

```css
:root {
  --font-ui: "Bloxwap Sans", ui-rounded, system-ui, -apple-system, "Segoe UI", sans-serif;
  --font-code: "Bloxwap Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
  --font-display: "Bloxwap Pixel", "Bloxwap Mono", ui-monospace, monospace;
}

body { font-family: var(--font-ui); }
code, kbd, pre { font-family: var(--font-code); }
.scoreboard { font-family: var(--font-display); }
```
